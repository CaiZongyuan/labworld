基座

让人和 Agent
理解同一间实验室。

Lab World 把设备、数字资产、空间关系与设备观测组织成共享的实验室世界模型。人和 Agent 基于同一份事实查看实验室、运行虚拟设备，并追溯操作结果。

01 · 持久世界

实验室、资产、对象、场景节点

从带版本的定义目录注册对象，以米和弧度放置场景节点，并用位于、包含、模拟关联对象——每条关系都记录其来源、操作者与时间。布局带版本管理；冲突的保存会返回 409 lab.layout_conflict，并保留你的草稿。

02 · 资产库

glTF 2.0 进，溯源出

上传自包含的 .glb 文件，名称、来源、许可与版本均为必填。服务端校验字节流、按内容哈希存储，并报告外部依赖、缺失几何体与解码失败。导入非法时保留上一个可用模型。

03 · 实时同步

带持久版本的 SSE

订阅世界后通过有界队列接收属性更新，并支持快照恢复。每个响应都带 X-Lab-Runtime: ready、x-request-id 与结构化错误信封。吊销凭据即刻终止既有访问。

04 · 人类与 Agent

两侧共用同一套契约

人用邮箱与密码登录——第一个账号成为 Owner，其后为 Member。Agent 使用作用域为 lab:full 的 API Key 认证，执行完全相同的业务操作。仓库附带示例脚本：注册世界、编辑布局、控制灯光、观测温度、运行离心机。

指令不等于
观测。

Lab World 从不把“请求的目标值”当作设备实际上报的结果。指令、观测与三维摆放是彼此独立的记录，各自带有时间、来源与质量——模拟读数与真实测量在任何时刻都可区分。

资产库

是定义，不是文件。

资产是可复用的对象定义，包含其模型、文档、溯源与许可——与任何具体对象的身份、配置和状态相分离。一个定义服务多个对象；一个对象可以携带多个场景节点。

产品方向

可理解、可操作，
也可验证的工作环境。

我们希望让 Agent 理解设备与任务，在虚拟环境中预演，并通过证据验证结果。当前 Lab World 提供共享信息底座与虚拟设备。真实设备执行和自主实验规划仍属后续方向。

当前可用

共享实验室世界模型

将设备身份、数字资产、布局与来源明确的观测关联起来。人和 Agent 通过同一份事实与接口理解实验室。

当前可用

虚拟设备与可追溯运行

运行虚拟灯具、传感器和离心机。分别记录命令、观测、任务与结果，让每个结果都能追溯到其来源。

后续方向

真实执行前先预演

后续将在连接真实设备前，先在虚拟环境中检验实验流程、设备接入与异常恢复。仿真结果仍需真实验证。

长期方向

以验证结果积累能力

通过可追溯的执行证据评估改进，并复用经过验证的流程。真实协议、机器人控制和自主实验规划仍属后续范围。

确定性预算

由 CI 守护的数字。

每个操作都带有可机器校验的预算——写入行数、SQL 语句数、负载字节、包体积——每次运行都会校验。预算只能通过附带前后证据的基线调整 PR 变更：先改证据，再改数字。

快速开始

安装、启动，
打开 Lab。
