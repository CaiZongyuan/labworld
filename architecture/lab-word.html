产品范围与架构 ​

Lab Word 的产品目标是实验室数字孪生。当前正式应用提供持久 Lab、独立 Entity、多节点场景、服务器资产库、版本化定义、布局编辑与人工关系登记及后端照明程序。术语见 CONTEXT。

模型与设备的关系 ​

text
Lab ──登记──> Entity（设备等对象）<──定义── Asset
                 │
                 └──由 Scene Node 呈现 <──外观── Asset Representation

这是当前已建立的 Foundation V1 身份关系：Equipment Model 是三维资产表示，Equipment Instance 是设备类 Entity；Scene Node 的身份与摆放独立于设备身份。同一模型可表示多台设备，同一设备也可有多个节点。登记时固定定义版本及快照；模拟与真实对象保留独立身份，静态对象无需 Binding。

已有实现与目标接入 ​

范围当前状态后续责任
通用应用壳、身份、成员、知识库现有应用代码为 Lab 提供宿主与共享能力
Lab 与持久资产库Member/Agent 共用世界、布局、关系、文件、照明与温度 API、可靠订阅更多设备程序与历史记录
Lab 导航与登录后默认入口已由显式组装接入保持宿主和 Lab 职责分离
Foundation V1体验已接受，规格/实施票已发布建立持久世界与后端虚拟设备运行
真实设备与协议接入后续范围按实际来源增加适配与执行合同

ADR 0005选择复用现有 SaaS 底座：Lab 拥有设备与布局业务，Core 保持身份、成员等公共职责。接入点见项目结构。

当前呈现层边界 ​

Lab 主入口使用对象目录、多节点场景和 Inspector，保存摆放、实例配置及引用，另一浏览器和 Agent 可读取同一世界。指针变换只编辑 Placement；位于、包含和模拟对应通过显式关系登记保存人工来源，空间关系共同拒绝非法环。独立复制创建新 Entity，多表示和移除节点保留身份；版本冲突保留页面草稿，显式重载后重试，见布局教程。定义支持、Binding 实现和当前可执行性分开；无观测时返回未知。照明在后端独立运行，命令接受和实际观测分开，停止保留最后观测，重启中断后需显式启动；见照明教程。布局版本与运行态分离；世界订阅提供持久版本、实体属性更新、有界队列、断线快照恢复和现有连接撤权，执行服务就绪与持久能力许可共同决定可操作性。离心任务与历史记录仍由后续切片提供。资产库在 /lab/asset 保留单模型预览；文件由 Core 生命周期保存，Lab 拥有稳定资产与表示引用。

温度传感器在后端以 1Hz 独立采样。每个属性保留值、单位、来源、时间和质量。心跳不刷新旧测量。停止后保留最后值，并在报告期限后过期。过期推进世界版本，布局草稿不受影响。

当前实现保持模型原始尺度，并在外部资源依赖、无几何或解码失败时反馈错误、保留前一个可用模型。每个节点独立加载并释放模型资源，选择一个实例不改写其他实例材质；World 快照返回节点及未放置对象引用的资产，模型恢复不依赖目录第一页。

Three.js 相关代码已随 Lab 页面按需加载，并纳入正式包体预算。预览的构建与软件渲染指标不代表目标硬件性能。

继续开发 ​

先按查看器指南观察现有功能。Foundation V1 从规格 #1及其实施票继续，接手入口为开发交接；职责规则见模块边界。
