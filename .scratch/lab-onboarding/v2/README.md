# Lab Word 视觉新手引导预览 v2

问题：用户能否在首次使用时认出永久操作入口，亲手完成搭建与设备操作，并在引导结束后继续使用同一个工作台？

2026-10-04，用户反馈希望获得“第一次使用很多 app 的视觉引导的感觉”，以便知道以后在哪里、如何操作。本版沿用已接受的工作台，把引导放在真实控件旁边。此前的 [v1 搭建向导](../v1/README.md)和刷新修复分支均保留。本版是隔离体验预览，正式应用尚未接入此引导。

## 打开

<http://127.0.0.1:5194/prototype/lab-onboarding>

从仓库根目录启动：

```bash
pnpm --dir .scratch/lab-onboarding/v2 dev
```

新 checkout 先安装仓库依赖，再安装锁定的预览依赖：

```bash
pnpm install --frozen-lockfile
cd .scratch/lab-onboarding/v2
pnpm install --ignore-workspace --frozen-lockfile
pnpm dev
```

此版本独立安装 Driver.js 1.9.0，并使用独立端口、依赖、浏览器数据和源码目录。v1 仍位于 5192；5193 已由其他进程使用，因此此版本选择 5194。

## 体验

首次进入自动聚光高亮 **创建实验室** 图标。按浮层指示操作普通控件：

1. 创建实验室，选择基础实验台场景。
2. 从工具栏的 **登记对象** 添加一台照明。
3. 从对象目录选中照明。
4. 切换到 **编辑布局**。
5. 修改右侧的三维坐标。
6. 使用工具栏的保存图标。
7. 切回 **运行查看**。
8. 在对象信息中启动设备程序。
9. 使用电源或亮度控件点亮照明。
10. 核对当前观测，再打开资产库。
11. 完成引导，回到原工作台。

14 个聚光步骤包含这些操作及位置说明。需要执行操作的步骤等待真实操作结果；坐标尚未修改时，继续按钮禁用。操作失败保留当前高亮和输入，重试成功才推进。

基础实验台场景包含实验台、烧杯和传感器；用户亲手登记照明后得到四对象布局。创建表单还提供完整八对象示例和空白网格。所有创建、登记、编辑、保存与设备控件在引导结束后保留。

浮层的 **跳过** 或 Escape 退出引导，普通工作台继续可用。问号入口恢复未完成的引导。完成后，问号入口提供 13 个操作位置的回顾；回顾使用下一步/上一步，不自动创建对象、保存布局或启动设备。

已经创建的对象、布局草稿及引导位置保留在本预览的独立存储中。刷新保留进度，并停止浏览器模拟程序；未完成的设备操作阶段会回到启动程序。完成过的引导不会因刷新自动重播。尚未提交的表单值只在当前页面保留。

预览工具条位于评估界面之外。先跳过浮层，再使用首次进入、布局修改、已完成、创建失败、保存失败和启动失败场景。重置只影响本预览。

## 真实性

- 实际运行：共享应用壳与 shadcn 组件、普通创建/登记表单、Driver.js 聚光/锚点定位、Three.js 场景、相机、点选、位置变化、观测驱动照明和浏览器存储。
- 浏览器模拟：身份、World API、设备程序、观测和失败。没有接入真实账户、数据库或物理设备。
- 持久数据键名为 `PROTOTYPE-lab-onboarding-v2` 与 `PROTOTYPE-lab-onboarding-v2-tour`，与 v1 分开。
- 仅照明和温度传感器提供本预览的模拟运行。资产库展示内置表示；离心任务、GLB 导入和 Agent 接入属于正式应用原有能力，不在本预览中执行。
- 房间沿用 Foundation v1 几何。正式实现需将场景模板和房间表示写入 Lab 合同。
- 三维摆放与人工登记位置保持独立。基础场景的烧杯和传感器带显式登记关系。
- 教学浮层使用简短的任务说明，普通界面不保留教学文案。回顾和正常操作共用相同入口。

## 验证

```bash
pnpm exec tsc -p .scratch/lab-onboarding/v2/tsconfig.json --noEmit
pnpm --dir .scratch/lab-onboarding/v2 build
node .scratch/lab-onboarding/v2/inspect-preview.mjs
node .scratch/lab-onboarding/v2/check-reload.mjs
node .scratch/lab-onboarding/v2/check-keyboard.mjs
```

完整浏览器检查包含 1600×1000 中文浅色、390×844 中文浅色、320×844 英文深色的全部 14 个位置，检查浮层留在视口内、没有盖住实际操作目标、没有页面横向溢出。三种尺寸的真实画布像素均非空。还检查 13 步位置回顾不增加对象或布局版本，跳过/刷新续接，以及创建和保存失败的原位重试。7 组旅程检查通过，没有页面错误。

重载回归在桌面和窄屏主动产生浏览器日志，检查日志确实写入后台文件、10 秒内没有重载通知、页面只加载一次、名称输入保留。Vite 排除运行日志、证据与构建产物，避免输出触发页面重载。测试在后台日志落盘的实际服务上运行。

键盘检查覆盖 Escape 跳过、问号续接、Enter 打开和提交表单，以及逐字输入负数、小数和保存结果。坐标框保留输入中的数字草稿，避免输入负号时恢复旧值。6 项检查通过，没有页面错误。

源码、截图、锚点矩形与像素计数位于本目录及 `evidence/`。截图文件名包含尺寸、语言和主题。测试使用 Chromium 与 SwiftShader，属于体验证据，不代表真实后端持久化或目标 GPU 性能。

## 留存

```bash
node .scratch/lab-onboarding/v2/capture-preview.mjs
```

捕获到本地独立分支 `preview/lab-onboarding-v2`，保留当前分支和用户 index。`node_modules`、`dist` 和服务日志不纳入捕获。目标分支存在时拒绝覆盖。

后续正式实施应带入此反馈：教学锚点指向永久控件，操作结果决定推进，失败时原位重试，进度与设备运行状态分别记录。预览的浏览器 store 不构成正式架构。
