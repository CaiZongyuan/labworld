## 返工与开发策略调整

| 观察到的问题                                        | 已发生的后果                                                                                               | 采用或保留的改进                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 并行修改共享消费者，真实合同与测试 fixture 对齐较晚 | WorldView、状态、趋势和记录多次重新组合；出现不存在的 Task wire 值、合法动态标签触发静态像素断言等不同问题 | 先核对共享消费者和真实 wire 值；以一个纵向公开旅程覆盖断线、重接和实际结果           |
| 多个堆叠候选重复完整检查                            | Source、Assets、工具候选重复验证共享代码；完整 CI 常需三十多分钟                                           | 汇总稳定候选后运行完整检查，局部修复复用输入未变的审查与检查结果                     |
| 定向绿色未复现完整 CI                               | 省略原先同进程前置用例；多次绿色仍不能定位原失败                                                           | 恢复有依据的前置条件，准确核对用例数量与顺序；绿色明确记为未复现                     |
| 首因和追踪归属不足                                  | 缺少首次公开失败原因；trace 超过 32 MiB；旧 ACK 可能属于不同 document/loader                               | 在原失败后保存有界公开原因；校验页面身份，追踪不完整时保留 unknown，维持原断言和期限 |
| 对已结束 Agent 发送消息却未激活                     | 已排队或预留被误报为正在运行，实际存在协调停顿                                                             | 恢复使用 followup_task；以 started ACK、进程或 ledger 确认实际执行。精确停顿时长未知 |
| 工作树、缓存和旧 checkpoint 积累                    | 清理前 76 个工作树，接手需反复核对旧状态                                                                   | 单一当前 checkpoint；历史放日志；任务收尾、恢复和每周核对消费者与可恢复归档          |

独立审查也发现并促成了有效修复：原启动器参数丢失、资产 enum/const 与其他约束未同时生效，以及 Python/Node 场景 hash 不一致。真实公共接口与几何验证有价值；但局部通过仍未带来旧 Source V1 的完整交付。策略调整节省了多少总工时，没有足够证据量化。
