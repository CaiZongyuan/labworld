# Lab Word 项目文档

Lab Word 面向实验室数字孪生。当前先建立设备模型的 Three.js 呈现层，再讨论设备摆放与真实状态关联。

## 选择你的任务

| 任务         | 从哪里开始                                                     | 可观察结果                         |
| ------------ | -------------------------------------------------------------- | ---------------------------------- |
| 启动现有应用 | [快速开始](quickstart.md)                                      | API 就绪、Web 注册页可访问         |
| 查看设备模型 | [Lab Viewer 预览](../guides/lab-viewer.md)                     | 在独立预览中看到设备并导入本地 GLB |
| 修改项目     | [项目结构](../architecture/project-structure.md)               | 找到应用组装与业务所有权           |
| 查阅接口     | [API](site:reference/api.md)与[配置](site:reference/config.md) | 定位当前生成合同与默认值           |

## 当前能力与计划

应用已有身份、成员、知识库、文件与任务等[平台能力](../guides/platform.md)。Lab Viewer v1 已能独立运行，预览画面已接受；正式 Lab 路由、登录后入口和生产懒加载的集成验收仍待完成。

本轮的本地 GLB 导入在浏览器会话内处理，不上传到服务器；设备数据接入、控制与场景摆放后置。[产品范围](../architecture/lab-word.md)说明这一边界；[呈现层计划](../plans/lab-viewer-m0.md)记录后续验收。

## 阅读与维护

教程逐步增加同一份 Lab 业务代码；独立指南以任务、前提、源码、命令、结果和失败边界组织。当前内容只声明仓库实际存在的能力，预览与计划分别标明状态。

中英文页面按章节配对，API 与配置从实现生成。修改功能时同步更新相关文档和[验证入口](../testing/t01-feedback-loop.md)，写作规则见[维护项目文档](../guides/maintain-docs.md)。
