# 恢复本浏览器的布局草稿

目标：逐字编辑 Placement，在同一浏览器刷新后继续私人草稿，再处理共享布局的版本冲突。

## 起始状态与本章变更

先完成[编辑布局与登记位置](edit-layout.md)。保留同一个 Lab、工作台和烧杯。使用普通 Member 登录，准备第二个浏览器。以下保存操作写入共享布局；输入和恢复本地草稿不写入服务器。

命令在仓库根目录运行。使用 Node 24 和 pnpm，无需 Docker。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 <http://127.0.0.1:5173/lab>，选择原 Lab 和烧杯，进入 **编辑布局**。本章由[数字输入](../../packages/views/src/lab/layout-editor.tsx)、[浏览器草稿](../../packages/views/src/lab/layout-draft-storage.ts)和[工作台上下文](../../packages/views/src/lab/workbench-context.tsx)实现。[布局保存](../../packages/server/src/lab/world/layout.ts)继续使用原版本检查。

## 输入、刷新与保存

1. 清空 **X (m)**，输入 `-`。输入保留，范围提示说明它还不是有效数值。**保存布局** 此时不可用。
2. 刷新页面，再进入 **编辑布局**。本浏览器恢复 `-` 和原布局基线；共享世界仍是先前保存的版本。
3. 继续输入 `.25`。输入为 `-.25`，有效 Placement 为 `-0.25 m`。语言和主题切换保留输入拼写与光标位置。
4. 刷新，再进入编辑。页面说明已恢复私人草稿。恢复本身不会保存布局，也不会更改人工登记的位置。
5. 点击 **保存布局**。看到 **已保存** 后刷新。此时显示已保存的摆放，私人草稿已清除。

位置和旋转的绝对值最多为 10000；旋转单位是 rad。缩放范围为 0.001–1000。无效文本保留并显示范围，不更新有效 Placement，也不能保存。修正输入即可继续。用三维工具拖动某个轴时，该轴显示新的有效值；其他轴的未完成输入仍保留。

## 与另一个浏览器比较

1. 在第一页把烧杯 X 改为 `2`，保持未保存。
2. 在第二个浏览器登录同一用户，打开同一 Lab。它显示服务器已保存的 World，不拥有第一页的私人修改。
3. 在第二页改工作台 X 并保存。第一页刷新后仍保留烧杯草稿和原基线，显示 **布局已改变，草稿已保留**。
4. 点击 **重新载入并保留草稿**，核对最新布局，再点击 **重试保存**。未修改节点和另一个用户新增的节点保留。双方修改同一个节点时，显式重试使用本地节点草稿。
5. 在第二页刷新，确认保存结果一致。人工登记关系及其来源保持原样。

草稿按部署、用户、Lab 和格式版本隔离。切换视图、Lab 或断线不把草稿交给其他上下文。同一用户重新登录原部署后可以恢复原浏览器草稿。其他用户和其他浏览器只能读取服务器已保存的布局。

## 失败后继续

浏览器存储不可用时，本页仍保留输入和草稿，页面提示离开前核对保存结果。先保存有效修改，再确认服务器 World。不要把本页保留当作已具备刷新恢复能力。存储恢复后继续编辑，浏览器即可再次保留草稿。

保存被拒绝或响应丢失时，草稿不会清除。先读取当前 World，核对是否已经提交。原基线与最新版本不同时，使用显式重载和重试；不要把刷新当作一次新保存。

需要采用服务器布局时，点击 **放弃草稿并重新载入**。确认重载成功后，该 Lab 的私人草稿清除。此操作不提交新布局、不改变设备程序。格式无效的本地内容不会自动应用，服务器 World 保持原样。
