# Newton 场景接入细化草案

状态：设计讨论中，2026-10-13。本文细化 [Issue #85](https://github.com/CaiZongyuan/labworld/issues/85) 的第二阶段，不是已实现的接口参考或实施票。Q4–Q16 的产品规则已确认，协议字段、转换验证及第三阶段衔接仍需细化。总体阶段见[设计记录](newton-source-sync.md)。

## 1. 已确认的结果与阶段边界

Newton 启动时加载适配器并主动报到。来源识别可以先于场景同步完成，无头与 GUI 使用相同接入方式。场景同步应保留原场景的对象、几何、尺寸、层级与位置；材质和灯光允许 Web 近似。

首次接入自动同步完整场景。对象增删和模型替换形成新版本，空闲时确认应用；持续变化的位置、旋转和关节由第三阶段更新。第二阶段不要求 Lab World 启动求解器，也不依靠用户提交运动命令。

“完整场景”需要有明确来源范围。首个 SO-101 闭环应包括机器人、试管、试管架和垫面，并保留适配器声明的其他静态可见几何。碰撞辅助几何、相机和灯光的处理须按源格式的用途区分，不能把每个 USD prim 都登记为一个 Entity。

每份独立仿真世界配置保留持久来源标识。同一配置重启或切换 GUI/无头复用对象；同机同时运行两份独立世界使用不同标识。首次在 Lab World 选择目标 Lab、生成接入配置，之后 Newton 加载配置自动报到和同步。来源权限仅覆盖自己在该 Lab 中登记的对象集合。

转换、上传和映射全部验证成功后，整份版本才成为有效场景。首次失败显示来源在线、场景同步失败；升级失败保留上次成功版本，报告具体失败对象。这些规则已在 Q7–Q9 确认。

Q10 已确认：来源采用单向同步，来源对象禁用编辑，场景布局和外观由源维护。资产的三维/物理内容在外部工具编写，业务信息通过独立描述文件导入，发布后固定版本；此规则见[资产设计](asset-definition-and-external-authoring.md)。

## 2. 最小数据合同建议

以下是业务合同建议，字段名和端点尚未定案，也没有现成 SDK 可调用。

| 数据 | 需要表达的内容 | 用途 |
| --- | --- | --- |
| 来源引用 | 来源标识、目标 Lab、当前接入身份 | 持久来源身份与某次运行、某份凭据分开；只能维护本来源对象。 |
| 资产引用 | 每对象的稳定资产 ID、明确版本和所选表示 | 业务定义与三维/物理内容一起解析，实例身份不使用资产 ID 替代。 |
| 场景版本 | 清单格式版本、结构版本、资源摘要、转换器版本 | 识别重复提交、待升级版本与所使用的资源。 |
| 对象字典 | 稳定 object key、名称、已知类别和来源路径 | 建立来源对象与 Entity 的对应关系。 |
| 原始层级 | 稳定 node key、parent key、对象归属、局部变换 | 保留源场景结构；它不是 Registered Location 或业务包含关系。 |
| 视觉资源 | 资源 key、内容 hash、类型、字节数、来源和许可信息 | 自动上传、校验与复用模型，不依赖作者本机路径。 |
| 可视目标 | 表示引用、节点路径、原点校正 | 对应一个能接收运动的视觉目标，避免 GLB 自动居中造成错位。 |
| 物理映射 | 稳定 body key、joint key、所对应的对象与可视目标 | 为第三阶段建立固定的采样字典；运行时数组索引不成为持久身份。 |
| 坐标说明 | 源轴向、手性、单位、变换层级和输出坐标约定 | 校验转换只应用一次，保持真实尺寸。 |
| 场景基准 | 源定义中的静态摆放及结构变换 | 与持续采样的当前位姿分开，作为来源版本和坐标校验的基准。 |

结构版本的判定应使用对象字典、层级、静态基准和资源内容，不因每一帧的位姿、速度或仿真时间变化而产生新版本。清单与初始状态需要关联同一来源的采样边界；具体边界协议在第三阶段细化。

版本记录需要保留上次已应用清单及资源引用，不能只修改当前 Asset 的 version 字符串。hash 相同只能证明字节内容相同，不能证明来源、对象或安装身份相同。

例如，同一个来源下的 `object_key=robot` 表达整机身份，`node_key=robot/shoulder` 表达一个可视目标；原始 USD prim path 另行保留作为来源映射。换模型时资源 hash 可以变化，但 object key 不应因为转换器重命名或文件路径变化而改变。原始 parent key 必须从源层级读取，不能根据物理关节链虚构。

## 3. SO-101 的对象与可视目标

| 来源结构 | 业务身份建议 | 可视与运动表达 |
| --- | --- | --- |
| SO-101 整机 | 一个设备类 Entity | 连杆分别有稳定可视目标及 body 映射，保持原连杆结构。 |
| 试管 | 独立 Labware Entity | 自由刚体运动独立于机器人，不能用夹爪动画代替。 |
| 试管架 | 独立 Entity | 保留原几何、尺寸和来源定位；kinematic 属性不自动赋予控制能力。 |
| 垫面及其他静态场景对象 | 按来源声明的对象分组登记 | 可以有视觉表示而没有 Runtime Binding。 |
| 碰撞辅助形状 | 保留必要来源信息 | 按源用途处理，不能把 guide 碰撞网格自动当成普通可见外观。 |
| 相机、灯光、视觉辅助节点 | 保留适用的表示配置 | 不因场景节点存在就成为设备 Entity。 |

这些分组是首个场景的适配建议。来源适配器应明确声明业务分组；Server 不根据网格数量、名称或三维重叠猜测设备能力、容纳关系和任务结果。Q13 已确认，未声明资产引用时可用通用模型导入并表达业务类别未知；显式资产引用的精确版本缺失则失败，不用通用模型掩盖错误。

本机原场景的七个 Robot link 是同一 Robot 下的直接子节点，物理关节另行连接它们。Mat 没有 RigidBody，Rack 有 RigidBody 但为 kinematic。因此只遍历 Newton body 会漏掉静态场景，按 USD 父子关系推导机器人关节链也会得到错误结构。场景描述与物理字典必须一起读取并校验。

必须保持三类结构的区别：来源中的视觉层级、Lab 中的对象关系、运动字典中的 body/joint。机器人七个连杆可以共享一个 Entity，同时拥有多个运动目标。

当前持久 Scene Node 没有 parent 字段，Motion 目标仅支持 node-root。因此，“保留原层级”还需要明确的来源结构记录和呈现映射，不能仅调用现有 layout API 就宣称完成。GLB 内部层级也不能自动成为 Lab 的业务关系。

现有 GLB loader 和 Viewer 保留文件内部的节点层级，但不同持久 Scene Node 仍在同一根下并列渲染。Motion 不支持按 GLB child path 或 bone 定位，也不根据 joint 数组自行计算机器人连杆位置。为复用当前 Motion，首个场景可以先为各物理 body 建立独立的可视根，并在来源清单中保留完整原层级；源层级如何在查看器中呈现仍需定案。

当前公开登记需要已有 catalog definition。通用 `model@1.0` 可表达没有控制能力的模型对象，但不能自动生成实验室分类或能力。Q13 的通用模型路径可复用其语义，同时仍需补充来源限定的资产与对象登记合同。

## 4. 场景提取与资源转换

建议由适配器在场景就绪后读取源场景和 Model，提取对象、原始节点路径、视觉资源、结构变换与 body/joint 字典。若场景来自 USD，优先使用原 USD 的可见几何和外观；Newton Model 的物理 shapes 不一定包含同等的视觉信息。

资源转换需要执行以下检查：

1. 解析源场景及依赖，区分可见几何、碰撞辅助形状与实例。
2. 导出 Web 可用的自包含表示，纹理内嵌或按服务支持的资源闭包打包。
3. 按已同意的规则转换材质，保留基础颜色、适用纹理和透明度；报告实际近似项。
4. 保留模型原点、相对变换和真实尺寸，记录 body-to-visual 校正。
5. 使用正式 GLB 校验器检查资源，再以已知源样本对照 Viewer 的实际世界变换。

原场景使用米制、Z-up，现有 Motion 使用右手 Y-up、米和 XYZW。适配器应统一坐标约定，并记录转换过程。当前 Viewer 会对 GLB 自动居中、贴底；直接将这个显示根当作物理原点会产生偏移。

推荐在来源侧进行提取和转换，再由 Lab World Server 沿用资产上传和 GLB 校验能力。源场景的依赖本就在 Newton 环境中，这也与单 Node Server 的既有边界相符。具体工具链需要固定版本和可重现验证。

本机已有可读取原 USD 的 pxr、能导入 USD 和导出 GLB 的 Blender，以及可导出 GLB 的 trimesh。trimesh 本身不能直接导入 USD，需要接收从 USD 提取的几何。仓库没有通用 USD 到 GLB 转换器。

本轮使用 Blender 5.4.0 Alpha（29ff43161222）完成一次小型实证：从原历史 USD 导入 Vial 可见表示并导出 293,200 字节 GLB，得到 3 个网格、2 个材质，保留 Vial 内部层级，并得到符合 Z-up 到 Y-up 变换的位置。没有运行渲染或仿真；该 Vial 没有图片，所以纹理转换尚未验证。临时产物及进程已清理。这不是生产工具版本定案或整场景验收。

这次导出的 Vial 根仍带原世界位姿。如果再给 Scene Node 设置同一位姿，会重复应用变换。生产表示应明确采用 body 局部原点加单独位姿，或采用另一种经过验证的一致坐标合同。导出器若已转换轴向，后续不能再次转换同一表示。

Blender 这次没有自动保留完整原 USD prim path。转换器必须主动输出 path 到节点和运动根的对应关系，不能用 `Mesh_001` 或数组序号当身份。原 USD 共 65 个网格，其中 32 个可见 default、32 个 guide、1 个隐藏 default；外观导出应遵循 purpose 和 visibility，而完整来源清单保留相应分类。

## 5. 建议的同步过程

| 步骤 | 对外行为 | 失败或重试 |
| --- | --- | --- |
| A. 来源上线 | 独立显示来源已连接 | 场景失败不伪装成来源离线。 |
| B. 准备清单 | 提取场景结构，生成资源列表和映射 | 显示具体源路径及失败原因。 |
| C. 准备资源 | 转换、上传和校验所需资源 | 按内容与上传状态复用已完成工作。 |
| D. 验证完整版本 | 检查资源闭包、key 唯一性、父子结构、坐标和映射 | 失败版本不得成为有效运动字典。 |
| E. 首次登记 | 整份版本通过后，自动原子登记本来源安装及身份对应 | 失败不启用部分对象，显示具体原因。 |
| F. 相同版本重接 | 复用已登记对象和资源 | 依靠持久来源映射，不能依赖短期请求幂等记录。 |
| G. 新版本到达 | 显示对象增删、资产版本和模型替换差异 | 活动运行不热替换字典；外部结构变化的观察边界在第三阶段细化。 |
| H. 空闲时应用 | 用户确认后提交版本切换 | 使用期望版本检查并发修改；冲突返回重新比较。 |

Q9 已确认整份场景版本校验成功后切换：首次失败显示“来源在线、场景同步失败”；升级失败保留上次成功版本。失败报告与当前已应用版本分别保留。

场景登记的事务原子性与资源上传不是同一件事。GLB 转换和网络上传先完成，数据库事务再发布场景对象、映射和引用。Q12 已确认来源同步的新资源先进入同步任务暂存区，失败可复用已完成工作，成功后发布；现有逐资产上传不能直接提供这种可见性，需要新增暂存发布合同。

取消仅释放本同步任务的引用并清理无其他消费者的暂存资源，不删除已发布资产、其他任务或 Recording 的依赖。相同 hash 可以复用字节，不意味着取得其他资源的删除权。恢复中断任务时先核对持久任务清单和实际资源，再决定继续或释放。

失败报告应包含阶段、源对象或资源路径、错误类型、可重试性和保留的当前版本。不得将占位模型、缺失对象或错误映射报告为完整同步成功。

## 6. 版本更新与来源编辑权

相同 object key 保留已有 Entity，新 key 建立新身份；删除项、节点移除与 Entity 归档要分别处理。ADR 0012 已要求由用户决定移除项是否归档，不能因来源中少一个节点就彻底删除业务对象或历史。

Q11 已确认：移除项不再有当前来源可视节点，Entity 与历史保留，并标记不在当前来源场景中。归档单独确认；来源版本更新不自动删除身份和记录。

来源场景的父子关系不自动证明真实物料的 Registered Location。导入和升级只处理显式声明的业务关系，不从视觉层级或几何重叠推断“包含”。

来源对象的 Placement 与外观先禁用本地编辑，更新只采用来源版本，因此不需要本地覆盖层或布局三方比较。应用时仍需检查期望场景版本、权限与活动观察状态，防止两个确认操作互相覆盖。实时位姿与持久源场景基准继续分开表达。

此规则限定外部来源模式。ADR 0012 中由 Lab World 监管的模板安装具有自己的布局规则，不据此改变其历史合同。

## 8. 现有限额与验收建议

这些是已核实的实现边界，不是新增预算：单文件默认 20 MiB，FILE_MAX_BYTES 最多可配置 100 MiB；GLB 展开资源预算 256 MiB；只接受自包含 GLB/data URI；一个 Lab 最多 1000 个 Scene Node。当前普通安装请求仅 4 KiB，Session snapshot 约 1 MiB，Recording manifest 2 MiB。新清单必须验证实际规模和载荷路径，不能因为 Motion 可承载 1024 个 body 就认为其他入口也支持同样规模。

第二阶段完成的验收建议：

- 来源已上线后，通过正常接入自动呈现声明范围内的完整场景，无需手工上传和登记。
- 独立对照源场景对象清单、几何尺寸、层级和多个静态世界变换；实际浏览器能加载对应资源。
- 同一来源重复接入保留对象身份；其他来源和人工对象不被覆盖。
- 资源缺失、非法层级、错误坐标和错误物理映射得到具体失败结果；失败不被算作成功。
- 活动运行期间新结构版本只显示待更新；空闲确认后应用，旧录制仍能解析自己的模型和映射。
- 原场景几何与材质转换的证据分别记录；已有历史 USD 或工具版本不能代替本次真实导入结果。

来源标识和对象 key 的组合维持身份连续性，场景版本和资源 hash 表达内容变化；两者不能互相代替。接入配置也不能以凭据内容作为来源标识，否则换凭据会错误地产生新对象。

上述产品规则已确认，正式字段、接口与兼容迁移在实施准备时定稿。第三阶段的起点、reset、来源事件和恢复规则见[实时观察合同](newton-live-observation-contract.md)，整体实施拆分见[主设计](newton-source-sync.md)。
