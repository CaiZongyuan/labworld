# Newton 来源识别、场景同步与实时状态同步

状态：产品方案已批准，2026-10-14 进入规格、实施拆分和开发。用户明确授权 to-spec、tickets 发布和 pm-development 直接开发，规格及拆票无需再次确认；沿用已确认合同和现有体验，直接实施，无需等待另一轮预览批准。本文记录 [Issue #85](https://github.com/CaiZongyuan/labworld/issues/85) 的设计和代码基线，不替代正式 GitHub 实施票或公开教程。正式协议、实际应用验证和交付仍按仓库流程进行。

## 已确认的阶段

| 阶段 | 用户要看到的结果 |
| --- | --- |
| 1. 识别运行来源 | Newton 启动时加载适配器并主动报到，无论无头或 GUI，Lab World 自动显示该来源。 |
| 2. 同步场景 | 将该 Newton 程序实际使用的场景同步到 Lab World，无需用户手工重建。 |
| 3. 同步实时状态 | Newton 自己的程序推进运行，Lab World 持续呈现其实际运动和设备状态。 |

阶段 1 的完成不代表阶段 2 或 3 已完成。场景和状态应来自同一来源及相符的对象映射。重复接入不重复创建整套对象，来源失联后显示最后已知状态和失联标识；这些要求沿用 #85。

Q4 已确认：第一阶段的识别建立在适配器主动报到之上，作为独立阶段验收，不要求先安装场景或创建仿真会话。来源在线只表示接入连接健康，不证明场景已经同步或物理仿真正在推进。该接入边界见 [ADR 0013](../adr/0013-source-presence-before-scene-synchronization.md)，领域含义登记为 [Lab Source](../../CONTEXT.md)。

Q5 已确认：第二阶段保留原场景的对象、几何、尺寸、层级与位置，材质和灯光允许采用 Web 可用的近似表现。

Q6 已确认：接入时自动同步完整场景；后续新增或删除对象、替换模型时提交新版本，在空闲时确认应用。持续变化的位置、旋转和关节归第三阶段实时状态同步。该规则沿用 ADR 0012 的场景版本边界，不在活动运行中替换对象字典。

Q7 已确认：每份独立仿真世界配置保留持久来源标识。重启、切换 GUI 或无头时复用原对象；同一电脑运行两份独立世界时使用不同来源标识。

Q8 已确认：首次在 Lab World 选择目标 Lab 并生成接入配置，Newton 启动入口加载该配置。后续启动自动报到和同步，来源只维护自己在该 Lab 中登记的对象集合。

Q9 已确认：以整份场景版本为单位校验和切换。转换、上传、映射全部通过后才应用；失败保留上次成功版本并报告具体失败对象，首次失败显示来源在线、场景同步失败。

Q10 已确认：Newton 到 Lab World 单向同步，来源对象先禁用编辑。布局、模型和场景内容由外部工具维护，Lab World 接收与呈现；来源模式的本地 Placement/外观覆盖与三方合并不进入本次方案。

Q11 已确认：来源移除对象时，移除对应来源可视节点，保留 Entity 和历史，标记不在当前来源场景中；归档另行确认。

Q12 已确认：来源同步的新资源先留在同步任务内，失败可复用重试，成功后发布；取消仅清理未被其他对象或录制引用的暂存资源。已发布的共享资源不进入这类清理。

Q13 已确认：未声明资产引用的对象先作为通用模型导入，业务类别和能力保持未知；已声明资产引用但精确版本不存在时报告失败，不静默降级。

Q14–Q16 已确认：完整资产包括型号与规格、实例配置字段、状态字段及单位、能力及参数说明、文档引用。通过独立描述文件编写并导入 Lab World，外部场景使用资产 ID/版本和对象 key。发布版本固定，更新显式升级；实例与历史保留当时版本。详细合同见[资产设计](asset-definition-and-external-authoring.md)和 [ADR 0014](../adr/0014-versioned-assets-and-external-authoring.md)。

Q17 已确认：场景和映射就绪后自动从来源当前实际状态开始观察，晚加入浏览器先取得完整状态再收更新，不要求 Newton 重置或重新执行。

Q18 已确认：Lab World 断开时 Newton 继续自身程序，观察与录制中断；重连从最新状态自动建立新观察段及录制，复用原对象，明确保留缺口，不自动重放或补出未收到的过程。

Q19 已确认：首版记录和显示来源明确上报的实验阶段、开始/结束及成功/失败/未知结果，作为来源事件。没有报告时保持未知，不从运动停止、回初态或进程退出推断成功，不伪造 Lab World 命令。

Q20 已确认：来源明确暂停/等待时保留连接，冻结最后实际样本；心跳不刷新测量，连接健康与运行进度分开，声称运行却长期不推进显示停滞。

Q21 已确认：每次实验/episode reset 保留末态与来源结果，结束旧观察和录制，再从新初态开始新段；来源继续，对象及资产身份复用，不跨 reset 插值。中途加入或断线分段明确不完整范围。

Q22 已确认：结构变化结束旧观察并保留旧版本末态，新版本确认后从当前来源状态加入。空闲指 Lab World 无活动观察段，Newton 本身可继续运行。

第三阶段的协议衔接、时间、来源事件与事实缺口见[实时观察合同草案](newton-live-observation-contract.md)。

第二阶段的合同、对象映射、失败恢复与验收建议见[场景接入细化草案](newton-scene-ingestion-contract.md)。草案中的未确认选择不会因记录在文档中而自动成为已接受决定。

## 适配器与 Newton 程序的关系

接入采用已确认的适配器主动报到方式。后续阶段由适配器读取正在运行的程序所持有的场景、Model 和 State，再向 Lab World Server 发布数据。这里的接入改动指在应用入口或回调中加载适配器，不是修改 Newton 库、求解器或策略算法。无头和 GUI 是同一类接入：GUI 是否绘制窗口不决定状态从哪里读取。

实施默认先采用本仓库启动包装器，利用原 Isaac Lab 的启动回调和 RecorderTerm 加载适配器，配置和实现保存在本仓库，原项目文件保持只读。其他 Newton 程序可使用相同合同的显式接入入口，但首版不承诺任意未接入程序零改动。尚未接入适配器的普通 Newton 进程，不会因进程存在就被现有服务自动发现。

本机 Isaac Lab 源码已提供环境创建前的 `--external_callback` 和配置中的 `RecorderTerm` 扩展点。前者可加载适配器，后者可在实际物理步之后、reset 前后读取状态；组合后的启动包装器尚未实际运行验证。采样应挂在物理或策略步进路径，不依赖 GUI 渲染回调，否则无头模式可能不会采样。

## 核实的实现基线

### 阶段 1：已有会话准入，缺少独立来源在线登记

[Machine](../../packages/server/src/core/machines/schema.ts) 保存凭据身份，不保存在线状态。[Machine 路由](../../packages/server/src/core/machines/routes.ts)提供创建和撤销，没有来源在线列表或心跳入口。

[Session 服务](../../packages/server/src/lab/sessions/service.ts)允许将外部 Machine 绑定到已创建的 Session，再通过 `publisher-admissions` 取得票据、lease 和 epoch。它要求已经有 Installation 和处于 starting 的 Session，因此不能单独证明阶段 1 已完成。[会话界面](../../packages/views/src/lab/simulation-session-controls.tsx)中的 Newton 可用提示来自服务配置开关，不是发现了正在运行的 Newton。

### 阶段 2：已有固定场景安装，缺少实际来源场景导入

[现有安装脚本](../../tools/newton-motion/install_scene.mjs)自动上传固定 SO-101 的十个 GLB，再创建 Installation。它不从活动 Newton 场景提取对象和外观，重复执行也没有来源身份驱动的映射复用合同。

[Installation 合同](../../packages/server/src/lab/sessions/dto.ts)已表达 object key、Entity、pose key、Scene Node 和 body-to-visual 校正。实际来源导入可复用这些含义，但还需要来源场景描述、模型资源处理和来源限定的登记合同。

用户已有的 IsaacLabTutorial 场景与仓库内置场景是不同模型。已有项目通过 NewtonManager 读取 Model 和 State，并导出原 USD 场景。本轮只读调查实际打开其历史 USD，确认 Robot、Vial、Rack、Mat 几何存在；这不证明当前程序再次运行成功，也不证明 USD 到 Web 表示的转换完成。原场景仍有 MDL 资源引用，转换需保留对象路径、坐标、原点与外观资源的对应关系。

原场景的优先复用背景见[原物理仿真计划](newton-backend.md)。该计划将训练策略接入列入后续；#85 若用已有策略验收，应明确只是复用现有程序，不增加训练任务。

### 阶段 3：已有运动与录制通道，缺少自主来源运行边界

[Newton 采样](../../tools/newton-motion/physics.py)从实际 State 读取 body pose、joint position 和 velocity，并进行坐标转换。[Motion 接入](../../apps/server/src/motion-ws.ts)与浏览器使用同一会话的固定映射。直播与可靠录制分别传输，不逐帧覆盖持久布局。

当前首帧必须符合 Server 固定启动快照；新 SO-101 安装采用受控模式。已运行的外部程序不能直接以当前状态建立观察起点。现有 publisher 还将网络连接结束与自己拥有的 Newton 运行结束绑定，需要为观察独立程序划清资源所有权。

来源自主任务不能直接冒充 Lab World 已受理的 Device Command 或 Device Task。若本阶段要显示自主程序的任务结果，还需要定义其登记与报告合同；运动本身不能证明任务成功。

## 实施顺序与可验收结果

这是实施拆分草案，尚未发布或领取票。每项进入开发前都需落实公开测试接口、教程与现有体验流程，不把这份顺序当成已经授权的无限实施运行。

| 顺序 | 完整结果 | 主要验证 |
| --- | --- | --- |
| 1. 来源识别 | 用户选择 Lab 生成配置，启动原 Newton 程序后自动报到，来源在线/离线可辨，无需先安装场景。 | 真实启动入口、GUI/无头、健康心跳、撤销、重复来源及其他 Lab 隔离。 |
| 2. 完整资产版本 | 描述文件与表示资源导入、固定版本和查询，离心机信息可查看，两个实例可共享定义但状态独立。 | 字段/单位、资源引用、多表示、不可变版本、错误引用、旧数据及录制依赖兼容。 |
| 3. 原场景自动登记 | 自动提取原 SO-101 场景，转换完整可见表示和稳定映射；重复接入不复制身份，源对象不可编辑。 | 原几何/层级/尺寸/多个世界变换，暂存失败与重试、移除项和空闲确认。 |
| 4. 当前过程实时观察 | 原程序自主动作，两个浏览器共享实际位姿/关节和来源观测，阶段/结果可靠记录。 | 一致起点、时钟映射、无命令依赖、正确只读绑定、当前/最后值、身体原点对齐。 |
| 5. 边界与恢复交付 | 暂停、每实验录制、reset、结构版本、断线/恢复和最后状态均符合已确认规则，教程可照做。 | 来源继续运行、旧 epoch 拒绝、未覆盖区间、新浏览器末态、失败/未知结果、保留资源与独立 E2E。 |

顺序 1 与资产准备不互相依赖，场景登记依赖来源与资产合同，实时观察依赖完整映射；边界和资源保留需与录制一起建设，不能最后才补正确性。实际票粒度与原生 blockers 在 reviewed 拆分后另行发布。

## 当前证据与尚待实现的验证

已完成代码消费者调查、原历史 USD 的读取、试管的小型 GLB 转换和两个相同模型的元数据传递验证。它们分别证明数据入口及部分转换可行，不证明整场景、包装器运行、GUI 暂停状态线程、外部遥测和真实多浏览器闭环已完成。

首个实际闭环优先使用原 IsaacLabTutorial SO-101 场景及现有程序，复用已有策略产生实际运行，不新增训练。固定仓库演示可作为协议/对照输入，不替代原场景同步证据。首版为本地桌面 Web、当前单 Lab 活动会话容量；任意场景、真实设备适配和 #76 的跨主机/公网/长测另行扩展。

已有基础仍需要新增来源在线合同、完整资产关联与多表示、通用场景清单和暂存、外部观察上下文及生命周期，不能套用 #85 早期仅复用固定通道的 1–2 日估算作为整个扩展设计的交付承诺。实施估算在验证包装器与整场景转换后按实际票给出。
