# Newton 单向实时观察与来源事件合同草案

状态：Q17–Q22 的产品行为已确认，2026-10-13；正式字段与兼容实现待开发验证。本文是 [Issue #85](https://github.com/CaiZongyuan/labworld/issues/85) 第三阶段的设计，不是已实现接口。决定见 [ADR 0015](../adr/0015-source-owned-runs-and-observation-segments.md)，前置合同见[场景接入](newton-scene-ingestion-contract.md)和[完整资产](asset-definition-and-external-authoring.md)。

## 1. 已确认的行为

来源自己推进程序。场景、资产和映射就绪后，Lab World 自动从当前实际状态开始观察；新浏览器加入时先取得完整状态。观察不要求来源重置或重新执行，来源对象禁用本地编辑，设备动作执行不属于此模式。

Lab World 或网络断开时，Newton 继续自身程序；旧观察与录制中断。恢复后建立新观察段和录制，复用对象及资产，明确未收到的区间。若来源程序实际重启，则 Source Run 也变化；不能把观察服务重启与来源程序重启当成同一事件。

首版记录来源明确报告的阶段、开始/结束及结果。未报告结果为未知，不从静止、reset、正常进程退出或通信成功推断实验成功。

来源明确暂停/等待时保持观察连接，冻结在最后实际样本；心跳只证明连接健康。每次实验/episode reset 保留旧末态与结果，结束旧观察和录制，再从新初态开始新段，对象及资产身份复用。

实际源结构变化结束旧观察，旧版本最后状态明确标记；新版本确认后从来源当前状态恢复。“空闲”指 Lab World 没有活动观察段，不要求 Newton 本身停止。

## 2. 三类数据与执行权限

| 通道 | 数据 | 处理方式 |
| --- | --- | --- |
| Motion | 实际 body pose、joint coordinates、序列和仿真时间 | 复用高频二进制通道与浏览器缓存；直播可替换待发旧帧，不逐帧写布局或 world_clock。 |
| 设备观测 | 资产声明的状态属性、值、单位、时间、质量 | 来源限定、字段校验、逐属性持久化与历史；心跳不刷新旧测量，未报告属性保留原时间。 |
| 来源事件与录制 | 程序/实验生命周期、阶段、结果、reset/场景边界和采样事实 | 独立可靠采集、去重、明确结束与缺口；不能用直播 latest-wins 代替完整录制。 |

关节与位姿的高频样本由 Motion/Recording 承载，不要求每帧产生设备属性数据库写入。设备观测和阶段转换按真实低频业务变化发布。具体频率依据源程序配置及现有预算验证，不改动求解周期来迎合 Viewer。

能力定义、来源实际提供的字段与执行许可分别表达。外部 Binding 采用只读观察策略，不自动创建内置 Device Program，不允许通过已有 Command 接口绕过只读模式。

## 3. 身份、字典和时钟

| 标识或时间 | 含义 |
| --- | --- |
| source_id | 某份独立世界配置的持久来源身份；重接、GUI/无头切换不改变它。 |
| source_run_id | 来源程序的一次运行；观察断线不使其变化，来源重启需要新运行身份。 |
| observation_segment_id | 固定场景版本、映射和时间锚点的一段接收；每段有独立录制。 |
| scene/asset version、mapping revision | 本段采用的精确结构、资源和 body/joint 顺序。 |
| lease / server epoch | Server 授权的当前发布代次，旧连接不能覆写新段。 |
| source simulation time | 来源真实物理时钟；来源可快于或慢于墙钟运行。 |
| observation relative time | 从本段起点计算的相对仿真时间，首帧可以为 0，不要求源时钟归零。 |
| episode 与其计数 | 来源实验/episode 边界及进度；不等同全局物理时钟。 |
| audit / received time | Server 收到事件的真实时间，用于审计及本地时效；不能冒充未知的源测量时间。 |

如果在源仿真时间 12 秒加入，本段首帧相对时间为 0，同时记录源时间锚点 12 秒。后续相对 0.2 秒对应同一源时钟下的 12.2 秒。这是观察时间映射，不是重放源程序前 12 秒。

源时钟回退、运行身份变化、结构版本变化或字典失配必须形成明确边界，不能通过修改时间戳隐藏。跨主机墙钟不同步时不以直接相减估算单向延迟。

## 4. 一致的观察起点

建议流程：

1. 完成来源授权、场景版本及完整资产引用验证。
2. 在源的有效采样点复制一份实际完整状态，附源运行、时钟、实验上下文和所用字典。
3. Server 以这份状态建立固定观察快照、外部观察上下文和 Recording。
4. 授予发布 lease 与票据，可靠采集保存精确初始帧。
5. Motion 使用与快照及可靠初始帧一致的字节开始发布，随后处理后续实际样本。

快照只冻结观察条件，不冻结来源程序。握手期间的样本需要有界缓存和明确处理；如果源上下文已经变化或缓存不足，应重新从有效当前状态建立起点，并标记未覆盖范围，不把缺失帧补成连续数据。

当前录制要求首帧 sequence=1、sim_time_ns=0、pose/joints 对应快照，Motion 初始字节与已写入 Recording 相同。这些一致性约束可保留，新增的是源当前状态与观察相对时间的映射，而不是放宽首帧验证。

## 5. 设备观测的来源上下文

外部报告需要绑定本来源的 Entity、资产版本、当前观察上下文与发布代次。类型和单位依据所采用资产定义及明确映射校验；Source Run 或段已结束的迟到消息不能变成新段的当前状态。

当前可信观测依赖 Binding、running Device Program Run 和服务 generation，外部通用遥测入口尚不存在。实现需要明确的外部观察上下文及其与现有读取规则的兼容，不为得到“当前有效”显示而伪造内置程序运行。

部分报告只更新实际提供的属性。温度没有新样本时保留原温度及其时间，新的转速和心跳不刷新它。来源未知测量时间明确为空；新浏览器能读最后设备报告，但必须保留旧段、质量和时效标记。

## 6. 来源实验事件

建议来源事件至少携带 source/run、实验标识、事件序列或稳定事件 ID、源时间、影响对象 key、类型和实际提供的结果/原因。字段名与正式 schema 尚待定稿。

| 事件 | 允许表达的事实 |
| --- | --- |
| experiment started / 当前实验上下文 | 来源明确报告的实验身份、已知参数、开始时间与是否中途加入。 |
| phase changed | 来源报告的阶段；来源没有阶段名称时保持未知。 |
| experiment ended | 来源报告的成功、失败、取消或未知，以及实际判据/结束原因。 |
| source state changed | 来源的运行、暂停、等待或结束；不能凭静止直接推断。 |
| reset / scene changed | 瞬时边界及前后上下文，不能以插值生成不存在的搬运。 |

来源事件与 Lab World Command/Device Task 记录分别表达。现有 Robot observation 的 phase 不要求 Command，可以复用其阶段语义；现有 Robot task 则强制关联已受理 Command，不适用于自主来源结果。新的结构化结果应明确来源类型，不生成虚假 Command 来满足旧表约束。

一次实验的结果与当前运行状态分别保存。旧实验成功后，新实验开始时不能保留“当前实验已成功”。录制数据完整性也与实验成败分别表达：一段完整记录可以包含失败实验，中途加入的记录也可能接收到明确成功结果。

## 7. 已核实的 Isaac Lab 生命周期

源码调查未运行新仿真，得到以下实际顺序：

- PHYSICS_READY 只表明 model/state 已创建，FK 初始化仍可能延后，不能直接当作有效初态。
- 显式环境 reset 写入状态并执行 sim.forward 后调用 record_post_reset，适合取得有效初态；get_state 会补 pending FK。
- 正常求解后调用采样 hook，再计算 termination/reward，record_post_step 在自动 reset 之前，能读取真实末态和原因。
- 自动 episode reset 清零 episode_length_buf，但正常全局 simulation time 不归零。物理 manager 重建/关闭仍可能重置时钟。
- 原任务 success、vial_lost、unstable_robot、time_out 有明确判据；done 是结束原因并集，不等于成功。reset 后某些旧结果保留到下一次 compute，需要按实验边界隔离。
- GUI 的 training pause 与 rendering pause 分别存在。training pause 可能停止后续 Recorder step hook；独立心跳可以使用缓存进度，而不能制造新 GPU 样本。跨线程状态读取仍需真实验证。
- 原默认 player 在成功后自动 reset 并继续；旧成功导出脚本则退出。不能把旧脚本退出伪装成来源仍在线或持续运行。

源适配器应在原程序的物理/reset hook 采样，使用独立网络 writer。它不拥有源求解器，断开仅关闭自己的观察连接与队列，不能调用当前受监管 publisher 的 run.close 结束外部程序。

## 8. 暂停、reset 和结构变化规则

Q20 已确认连接健康与物理进度分开：来源明确暂停/等待时保持连接并冻结在实际末样本，心跳不刷新测量；声称运行却长期不推进时显示停滞。现有 Server 在 running 下仅凭仿真时间 5 秒不推进便中断，须新增来源状态合同。

Q21 已确认每次实验/episode reset 结束旧观察段及录制，在保留末态和来源结果后，以新初态开始新段；源程序不因此停止，对象/资产身份复用，不跨 reset 插值。中途加入与网络缺口分别标记。同一实验因重接形成多个段时关联同一来源实验标识，不伪装成多次实验。

Q22 已确认实际源结构变化结束旧观察，保留并标明旧版本最后状态；新版本待用户确认后从当前源状态开始新观察。“空闲”指没有活动 Lab World 观察段，不要求 Newton 自身停止。活动观察不使用旧字典解释新结构。

Episode、source clock 与结构边界各有明确作用。只发生 reset 而字典不变时复用场景/资产版本；模型、结构或业务定义实际改变时应用新版本。源时钟重建不继续使用旧时间锚点。

## 9. 最后已知状态与恢复

来源失联后，已打开浏览器冻结最后实际姿态。新浏览器及 Server 重启恢复也需要受授权的最后已知姿态快照及时间、版本和来源上下文，不能退回初始布局并把它称为最后状态。

现有低频观测已持久保存，但高频末帧只有活动 Gateway 缓存；已结束 Session 不能再取得 Viewer 票据。建议新增最后已知状态的读取合同，可利用已验证缓存的边界快照及可靠 Recording 前缀恢复，不增加每帧布局或数据库写入。

正常断开、异常终止与恢复必须分别验证快照来源和持久程度。只能恢复到最后可靠样本时显示其实际时间和范围，不能宣称恢复到尚未保留的最后直播帧。最后状态不允许继续外推运动或暗示设备仍实时在线。
