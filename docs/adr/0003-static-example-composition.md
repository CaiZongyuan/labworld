# 在构建时组合可独立增减的参考业务

模板需要支持零个、一个或多个参考业务，并在增减示例后保持通用 UI 和其他示例完整。采用源码层面的显式装配：每个示例持有自己的前端接入入口与所有权清单，应用入口组合其页面、导航、翻译、通知解析和可选设计系统场景；通用壳和 SaaS Core 不导入具体示例。开发者增减注册后重新构建，UI 按实际组合呈现。

这一选择延续[可移除真实示例](0002-executable-removable-reference.md)的目标：示例的源码、独占依赖和双语教程可以真正裁剪，并通过 Core-only、双示例及分别移除的构建与页面验收证明独立性。代价是更换示例需要重建和部署，同时必须维护多示例所有权、标识冲突和共享依赖检查。部署开关和管理员运行时启停将涉及额外的数据、后台任务与权限生命周期，本轮不承担这些合同。

通用首页与设置始终保留；默认业务入口由应用组合配置，目标移除或无权限时回到通用首页。多个参考业务仍属于同一 Organization，沿用[单企业部署](0001-single-organization-deployment.md)的决定。示例移除只改变模板工作副本与派生产物，保留迁移历史并遵守现有干净工作副本要求，不操作生产数据库或对象存储。

此 ADR 继承模板的目标架构。Lab Word 当前保留通用壳合同与 `assembleApp` 校验，实际组装点只注册知识库；便签源码仍在。历史模板的完整所有权清单、增删工具与组合验收不能据此视为本副本已实现。Lab 沿此贡献接口接入，UI 合同见[设计文档](../ui/design.md)。
