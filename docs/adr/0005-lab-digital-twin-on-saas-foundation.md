# 在现有 SaaS 底座上发展实验室数字孪生

用户确认本项目的产品目标是实验室数字孪生，并选择将 Lab Viewer 接入现有应用，复用其 React 界面与 SaaS 基础能力。实验室布局、设备模型、设备实例及后续状态关联归属 Lab 业务，沿用 [ADR 0003](0003-static-example-composition.md) 的显式组装和 Core 独立性，3D 页面按需加载。

这条路线保留了已有身份、成员与通用界面的投入，同时要求长期维护 Lab 自身的业务边界及资源所有权。相比独立学习 Demo，Lab Viewer 将持续演进为实际产品的可视化入口；相比将设备概念放进 Core，该边界使平台能力继续可独立复用。

Lab 是左侧边栏的首要业务入口和登录后的默认业务入口；用户接受 v1 后进一步要求资产库替换主导航中的知识库，既有知识库路由与数据保留兼容。首阶段按单设备闭环、五类资产场景逐步验收，优先桌面 Chrome，接受逐项核对的 CC0 / CC BY 资产。

保留知识库兼容与依赖 ADR 0003 显式组装的部分已由 [ADR 0009](0009-lab-word-product-only.md) 取代；Lab 与平台能力的边界继续有效。

用户进一步明确当前工作聚焦 Three.js 呈现层：在页面选择或拖入本地 GLB，附带预置示例，完成模型查看与点击选择。M0 建立静态可视化和设备实例身份；现实数据、设备状态、现场对应和控制能力留待未来阶段讨论。具体呈现层交付见[方案讨论稿](../plans/lab-viewer-m0.md)。
