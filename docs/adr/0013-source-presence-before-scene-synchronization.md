# 外部来源主动报到，在线状态先于场景和会话登记

决定日期：2026-10-13。用户在 [Issue #85](https://github.com/CaiZongyuan/labworld/issues/85) 的 Q4 访谈中确认：Newton 启动时加载适配器并主动向 Lab World Server 报到，Lab World 自动显示该来源；无头和 GUI 采用相同接入方式。来源识别作为独立阶段，不要求先建立 Scene Installation 或 Simulation Session。这让接入后的来源可以先被识别，再分别同步场景与实际状态；代价是需要独立维护来源准入、在线状态及其与后续场景和运行的关联。

来源在线只证明接入连接健康，不能代替场景同步完成、对象状态有效或物理运行进度。采用主动报到避免依赖本机进程扫描，也适用于后续现实环境的适配器。

## 来源身份与首次授权

用户在 Q7–Q8 确认：每份独立仿真世界配置保留持久来源标识。同一配置重启或切换无头与 GUI 时复用对象，同一电脑运行两份独立世界时使用不同标识。首次在 Lab World 选择目标 Lab 并生成接入配置，之后由 Newton 启动入口加载，自动报到和同步；来源仅维护自己在该 Lab 中登记的对象集合。

相比每次启动创建新来源或按主机合并所有世界，这保留重复接入的对象身份，并隔离独立运行。代价是维护持久来源配置、授权范围和来源对象映射，而不能只依赖一次性会话票据或短期请求幂等记录。

## 场景版本的完整切换

用户在 Q5–Q6、Q9 确认：首次接入自动同步完整场景，保留原对象、几何、尺寸、层级和位置，材质与灯光允许 Web 近似。后续对象增删和模型替换提交新版本，空闲时确认应用；持续运动独立同步。模型转换、资源上传和映射校验全部通过后才切换有效场景，失败保留上次成功版本并指出失败对象；首次失败表达为来源在线、场景同步失败。

相比启用部分成功对象或在活动运行中替换字典，这保留完整可校验的场景与运动对应关系。代价是需要准备中的版本、完整资源校验和最后的原子登记。用户在 Q12 确认来源同步的新资源在任务内暂存，失败可复用重试，成功后发布；取消只清理无其他对象或录制消费者的暂存资源。现有逐资产发布需要相应的暂存合同。

本决定补充 [ADR 0012](0012-newton-scene-templates-and-independent-replay.md) 的接入边界，并沿用其空闲时确认场景升级的规则。外部程序的观察生命周期和录制恢复见 [ADR 0015](0015-source-owned-runs-and-observation-segments.md)；本决定不改写既有受监管运行合同。阶段和已核实基线见[设计记录](../plans/newton-source-sync.md)。

## 单向同步与场景编辑权

用户在 Q10 明确：Newton 到 Lab World 采用单向同步，来源对象先禁用编辑。源场景的布局、模型和物理内容由 Blender、Isaac Sim/Isaac Lab 或 Newton 程序维护，Lab World 接收并呈现场景与实际状态。接入确认、资源校验、版本确认和协议回执不赋予 Lab World 向来源修改场景或执行设备动作的权限。

此来源模式采用来源权威的场景版本，不维护同一来源对象的本地 Placement 或外观覆盖，也不需要为此模式构建布局三方合并。版本及权限的并发检查仍然必要。该选择补充 ADR 0012 的场景来源模式；其受监管模板安装的本地布局规则不据此推及外部来源对象。资产信息的编写及版本规则见 [ADR 0014](0014-versioned-assets-and-external-authoring.md)。

用户在 Q11、Q13 确认：来源移除对象时仅移除来源可视节点，保留 Entity 与历史并表达其不在当前来源场景中，归档另行确认；未声明资产引用的对象先作为通用模型导入并保留未知业务类别，显式引用却缺少精确版本时失败。这使场景的当前内容、对象身份和资料完整性分别表达。
