# 可替换物理后端，场景模板与录制分别保留身份和历史

决定日期：2026-10-10。用户在 Q1–Q29 的设计访谈中确认：Lab Word Server 保留实验室权威状态和访问边界，物理仿真是可选扩展，首版交付一个生产后端。先验证已有 kitless Isaac Lab + Newton/MJWarp 场景在 WSL Ubuntu 的单环境链路，必要时加入 MuJoCo CPU 对照，再依据接触正确性、交互表现和适配成本定案。相比直接固定引擎或同时建设多个后端，这利用已有场景并让实测决定复用价值；代价是先完成受控验证和依赖固定。无需启动 Isaac Sim Kit 的目标保留。

## 场景身份与运行边界

Lab Scene Package 是可复用模板，Scene Installation 是某个 Lab 内的安装及对象映射。不同安装拥有独立 Entity；更新原安装时，相同 Key 保留身份，新 Key 创建对象，移除项由用户决定归档。升级在空闲时经差异检查显式应用，保留本地布局修改并提示冲突。相比分发一个 Lab 的身份快照或自动覆盖两端状态，这让模板复用和实验历史保持明确；代价是维护安装映射、版本和升级差异。

Simulation Session 表达多个对象共享的物理世界，与单设备 Device Program Run 分别记录。首版每个 Lab 最多一个活动会话，一次运行一个安装的绑定对象集合，多浏览器共享观察；其他 Lab 对象保持已有行为。服务监管明确配置的 Python 桥接进程及其资源，运行固定启动快照。布局编辑用于下次普通 Start；Reset 取消在途任务、结束旧会话，再从原快照创建新会话与新录制。暂停冻结仿真时间和任务进度，真实审计时间另行保留。这保留了每次实验的条件，代价是需要明确切换到新布局和管理生命周期。

同一机器人在途任务拒绝冲突动作，取消显式表达。服务、求解器异常或录制写入失败会停止/中断会话及在途任务，结果不确定的命令保持未知，已确认完成的任务保留原结果。用户显式启动新会话，不自动重放动作。

## 录制与资源所有权

一会话一录制，自动采集初始快照、运动、命令、逐属性观测和任务状态转换，固定当次场景、对象映射、实际参数及依赖版本。历史状态从快照与事件重建，缺少前序值显示未知，时效按历史时间判断。运动缺口显式标记并暂停，插值仅在有效连续片段内进行。

录制独立保留并显式删除；所需版本和资产一同保留，普通设备历史清理不影响它们。Core 文件引用由 Recording 正式消费，删除仅释放自己的引用。相比事后从有限期历史拼装或随当前资产更新改写实验，这保持完整历史和可追溯资源；代价是独立管理容量、引用与录制故障。故障保留已写入片段并明确完整性。

## 浏览器与外部渲染

同一录制用于无需 Lab Word Server 或求解器的浏览器 Replay，以及 Blender/UE5 的离线渲染。外部导出采用主 USD stage、相对路径资源、连杆和试管的时间采样变换及实验事件文件。物理结果由录制提供，渲染端不重新求解；材质、灯光和相机可分别配置。相比绑定引擎 viewer 或逐帧复制网格，这让三个呈现入口共享实验事实；代价是验证坐标、原点、时间映射与两个工具的实际兼容组合。

公开入口首版播放已发布示例，本地工作台查看自己的录制。发布生成显式选中实验的公开副本，保留必要实验信息、版本和素材署名，以别名表达操作者；内部账户标识和请求键保留在原始记录。公共页面任意文件导入、浏览器设备程序、远程实时控制及 Lab Word 自动调用渲染器留到后续范围。
