The foundation

A shared world
for people and Agents.

Lab World organizes equipment, digital assets, spatial relationships and device observations in one shared laboratory world model. People and Agents inspect the same facts, run virtual devices and trace results through the same interfaces.

01 · Persistent world

Labs, assets, entities, scene nodes

Register entities from a versioned definition catalog, place scene nodes in metres and radians, and relate objects with located in, contains and simulates — each relationship recorded with its source, actor and time. Layouts are versioned; a conflicting save answers 409 lab.layout_conflict and keeps your draft.

02 · Asset library

glTF 2.0 in, provenance out

Upload self-contained .glb files with a required name, source, license and version. The server validates the bytes, stores them by content hash and reports external dependencies, absent geometry and decoder failures. An invalid import keeps the previous usable model.

03 · Live sync

SSE with persistent versions

Subscribe to the world and receive property updates on bounded queues with snapshot recovery. Every response carries X-Lab-Runtime: ready, an x-request-id and a structured error envelope. Revoking a credential ends existing access.

04 · Humans and Agents

The same contract, both sides

People sign in with email and password — the first account becomes Owner, later accounts Members. Agents authenticate with API keys scoped lab:full and perform the identical business operations. Example scripts ship for registering a world, editing a layout, controlling lights, observing temperature and running centrifuges.

Provenance in every reading

A command is not
an observation.

Lab World never lets a requested target stand in for what a device actually reported. Commands, observations and placements are separate records, each with its own time, source and quality — and simulated readings stay distinguishable from real measurements at all times.

The real workbench

Not a mock-up. The application.

Asset library

Definitions, not files.

An asset is a reusable object definition with its models, documents, provenance and license — separate from any concrete object’s identity, configuration and state. One definition serves many entities; one entity may carry several scene nodes.

Product direction

An environment to understand,
act and verify.

Our direction is a work environment where Agents understand equipment, rehearse work and verify results. Today, Lab World provides the shared information foundation and virtual devices. Physical execution and autonomous planning are future work.

Available today

A shared laboratory world model

Equipment identities, digital assets, layouts and observations stay connected. People and Agents use the same facts and interfaces to inspect the laboratory.

Available today

Virtual devices and traceable runs

Run virtual lights, sensors and centrifuges. Keep commands, observations, tasks and results distinct, so each outcome can be traced to its source.

Next direction

Rehearse before physical execution

We aim to test workflows, equipment integrations and failure recovery in virtual environments before connecting real devices. Simulation results still need real-world validation.

Long-term direction

Improve through verified outcomes

Use traceable execution evidence to evaluate changes and reuse proven workflows. Physical protocols, robot control and autonomous planning remain future work.

Deterministic budgets

Numbers the CI defends.

Every operation carries a machine-checkable budget — rows written, SQL statements, payload bytes, bundle weight — verified on every run. A budget changes only through a baseline-adjustment pull request with before-and-after evidence: first change the evidence, then the number.

Quick start

Install, start,
open the Lab.

No Docker, no database server, no toolchain beyond Node and pnpm. The embedded database initialises and recovers before HTTP opens; your data persists in data/. In production the same service hosts the built web app same-origin.

The first account becomes Owner; later accounts are Members. Agents join with an API key.
